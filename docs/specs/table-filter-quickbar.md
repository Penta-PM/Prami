## 2. 결정 (Dev는 이 결정을 따른다)

### 2.1 형태 — 필드 버튼 = 칩
- 표 위 필터 바에 **고정 필드 버튼**이 항상 보인다: 비활성 `[상태 ▾]`, 활성 `[상태: 비활성,중지 ▾]` + 형제 `[×]` 버튼(버튼 중첩 금지). 값은 쉼표, 넘치면 "+N"·말줄임(최대 폭).
- 버튼을 누르면 그 필드 편집 팝오버가 바로 열린다(열 선택 단계 없음). 걸린 조건도 같은 버튼으로 바로 편집.
- 고정 아닌 필드는 **"＋ N개 더"**(필드 목록 → 같은 편집기). 해당 필드에 조건이 걸리면 바 안에 활성 버튼으로 나타남(고정과 같은 모양). 없으면 "＋ N개 더" 숨김.
- 별도 "적용된 필터" 칩 줄은 없앤다(필드 버튼이 곧 칩 — 중복 표시 방지).
- 열 머리글은 지금처럼 점 표시만(버튼 없음, #32·§2.5-3 유지).
- 접근성 이름: 버튼 "{열} 필터" / 활성 "{열} 필터, {값} 적용 중", × "{열} 필터 해제"(기존 이름 유지).

### 2.2 표별 고정 필드 (코드 설정, 열 정의 플래그 `filter.quick: true` — `pinned` 이름은 열 고정용이라 사용 금지, 서버 화이트리스트 타입 `ColumnFilterDef` 에 넣지 않음)
| 표 | 고정 | ＋ 더 |
|---|---|---|
| 사용자 | 이름·부서·역할·상태 | 이메일·최근 로그인 |
| 공지 관리 | 제목·작성일(필드 id publishedAt — 화면 머리글 "작성일" 유지)·작성자·중요 | — |
| 파츠 매핑 | 모델 | — |
| 내 견적 목록 | 일자·제품·내용 | 견적번호·금액·통화 |
| 가격 | 단가 유형·상태·단가 | 통화·품목상태·비고·(관리) 가격 변동 |
| 원가 | 통화·원가·상태 | 단위 |
| 감사 | 일시·사용자·행위·결과 | 대상·IP |
- 권한으로 숨는 필드는 바·URL 화이트리스트 어디에도 없음(기존 그대로). 사용자별 고정 필드 변경은 비범위.

### 2.3 적용 규칙
- **enum(다중 선택): 체크 즉시 적용**, 팝오버는 열린 채. 클라이언트 표는 즉시, 서버 표는 마지막 토글 후 **400ms 디바운스**(여러 개 체크 = 요청 1회). 팝오버 안 "선택 해제".
- **text**: Enter 또는 "적용"(입력 중 요청 없음 — 한글 조합·서버 부하). 포함/같음은 2버튼 토글, 기본 포함.
- **date**: 프리셋 **오늘·최근 7일·최근 30일·이번 달**(누르면 즉시 적용) + 시작·종료 입력은 Enter/적용. 감사는 기존 KST 해석.
- **number/money**: Enter/적용. **money 팝오버 상단에 통화 라디오**(단일 통화가 정해지지 않았을 때) — 적용 시 통화 `in` 조건과 범위를 함께 기록(두 조건 동시 검증, 10개 한도 포함). 통화 필드가 "＋ 더"에 있어도 단가 버튼 요약에 통화 표시.
- 한도·검증·제어 문자·trim·중복 제거·이스케이프 규칙 무변경(`validateCondition`).
- **서버 표 히스토리: 필터 변경은 `router.replace`**(즉시 적용으로 뒤로가기 기록이 쌓이지 않게, 클라이언트 표와 통일). 정렬·페이지 이동은 현행 유지.

### 2.4 경쟁 조건 수정 (즉시 적용의 전제 — PR-1 필수)
- **R1 낡은 기준값**: 서버 `go`·클라이언트 `setFilters` 가 마지막 렌더된 URL 기준으로 다음 조건을 만들어, 커밋 전 두 번째 체크가 첫 체크를 지움 → 정렬의 `pending-sort` 와 같은 방식으로 "보낸(대기 중) 조건"을 ref 로 들고 다음 변경의 기준으로 사용, URL 반영 시 정리.
- **R2 이동 순서 역전**: 빈 쿼리 이동(빈 상태 저장 await 후 이동)이 뒤의 비어 있지 않은 이동을 덮을 수 있음 → `navigateView` 에 **순번 토큰**, 다음 요청이 나간 이동은 버림.
- 서버 표 `useTransition` 의 `isPending` 으로 바에 `aria-busy` + 진행 표시(현재 없음). 바 컴포넌트 정체성 유지(재마운트로 팝오버가 닫히지 않게).
- 라이브 영역 안내는 마지막 변경 후 ~300ms 에 1회.

### 2.5 건수·한눈에
- **건수는 바 오른쪽 끝에 항상**: 클라이언트 "N건" / 필터 시 "전체 N건 중 M건". 서버 표도 바에 "총 N건"(하단 페이지네이션은 유지), 필터 시 "조건 K개" 덧붙임.
- "필터 초기화"는 바 끝(노출 조건·범위는 §6 Q1 B 그대로 — 페이지 필터 포함).
- **기존 페이지 필터(가격 분류 연쇄·날짜 기준·검색, 원가 제품군 탭)**: 동작·URL·위치 순서 무변경, **같은 카드(표면) 안에 묶어** 바로 위에 배치(`leading` slot) — 걸린 조건을 한 곳에서 읽게. 같은 의미의 열 필터는 여전히 만들지 않음(§2.4).

### 2.6 팝오버
- 기존 `Popover` 재사용. **마우스 이탈로 닫지 않음**(입력 UI — InfoHint 규칙은 InfoHint 한정). Esc·바깥 클릭 → 닫힘, 포커스는 그 필드 버튼. 모달 안 동작(§7 Q2) 유지.
- 포커스: × 후 같은 필드 버튼(고정 아닌 필드라 버튼이 사라지면 "＋ N개 더"), 초기화 후 첫 필드 버튼.

### 2.7 320px
- 바는 줄바꿈(가로 스크롤 없음, 모든 버튼 접근 가능), 버튼 글자 12px, 건수는 다음 줄. 모바일 전용 패널(C)은 만들지 않음.
