3. **현재 origin/main 과 같은 코드**(Dev 작업 브랜치가 아닌 main 기준 — 미머지 마이그레이션이 섞이지 않게)에서, 위 DB 를 대상으로 `pnpm db:migrate` 실행.

## 2. T2 — 재발 방지 (Dev, 작은 PR 1개)
1. **머지 체크리스트**: `docs/pipeline/verification.md` 에 "마이그레이션(`drizzle/*.sql`)이 포함된 PR 은 머지 직후 LAN 개발 DB 에 `pnpm db:migrate` 적용 + 적용 목록 확인 후 머지 보고에 기록" 단계를 추가.
2. **부팅 시 감지**: 개발 서버 기동 시(instrumentation) 미적용 마이그레이션이 있으면 콘솔에 눈에 띄는 경고(파일명 목록 + `pnpm db:migrate` 안내). 운영(Vercel) 빌드·런타임 동작은 바꾸지 않음. 자동 적용은 하지 않는다.
3. **부가 기능 실패 격리**: 원가 비중(`getCostRatios`)은 보조 정보이므로 실패해도 가격정책 화면 전체가 죽지 않게 한다.
   - 오류는 서버 로그에 남기고, 관리 표의 원가 비중 칸은 '—', 표 위에 관리자용 안내 "원가 비중을 계산하지 못했습니다. 관리자에게 문의하세요." (원가 열람 권한 사용자에게만 — 권한 없는 사용자에게는 원래 열이 없음).
   - 가격 행 조회(본 기능) 실패는 기존대로 오류 화면. 격리 대상은 보조 쿼리만.
   - 알림 종: `/api/notifications` 실패 시 드롭다운 오류 상태로 표시하고 폴링은 다음 주기에 재시도(이미 그렇다면 테스트만 추가).

## 6. 보완 — LAN :3000 이 Dev 워크트리에서 실행될 때 (2026-10-21, Main msg_011f4cff3c74)
환경: 사용자 지시로 LAN :3000(`pnpm dev:lan`)이 **Dev 워크트리의 현재 체크아웃**을 핫리로드로 서빙(Orca 터미널 "LAN :3000 (Dev)"). `.env.local` 은 Main 원본으로의 심볼릭 링크(같은 LAN DB).
1. **서버**: Dev 는 :3000 서버·그 터미널을 종료·재시작하지 않는다. E2E 는 기존대로 별도 포트·`.next-e2e`. `.env.local` 수정 금지(Main 원본이 바뀜).
2. **노출 인지**: Dev 워크트리의 체크아웃·미커밋 변경이 사용자에게 바로 보인다. 깨진 중간 상태를 오래 두지 않고, 큰 리팩터링·실험은 별도 임시 git 워크트리(서빙되지 않는 경로)에서 한 뒤 가져온다.
3. **미머지 마이그레이션 규칙** (브랜치에 새 `drizzle/*.sql` 이 생길 때):
   - 마이그레이션은 **추가형만**(테이블·컬럼·인덱스 추가, nullable 또는 기본값 있는 컬럼). 삭제·이름 변경·타입 변경 등 파괴적 변경은 Plan 에 먼저 되묻는다.
   - 그 브랜치를 Dev 워크트리에 체크아웃하기 **직전에** LAN DB `pg_dump` 백업 → 그 브랜치 코드로 `pnpm db:migrate` 적용 → :3000 이 깨지지 않게 한다. 적용 사실(파일명·백업 경로)을 Plan·Main 에 짧게 보고.
   - **한 번 LAN DB 에 적용한 마이그레이션 파일은 수정하지 않는다**(drizzle 기록 해시 불일치). 바꿀 게 있으면 새 마이그레이션을 추가.
   - PR 이 폐기되거나 마이그레이션을 되돌려야 하면 백업으로 복원하고 Plan·Main 에 보고.
   - 추가형 스키마라 main 코드(다른 브랜치)로 돌아가도 동작해야 한다(새 테이블·컬럼을 몰라도 기존 쿼리 무영향) — 이것이 추가형만 허용하는 이유.
4. **반영**: 이 §6 을 `docs/pipeline/verification.md` §3 에 Dev 가 다음 PR(원가 매핑 열·모달 PR)에서 함께 반영.
