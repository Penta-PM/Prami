## 2. 결정 (사용자 확인 + Plan 기술 결정 — Dev는 이 결정을 따른다)

### 2.1 저장 위치 (Q1 A)
1. **서버 DB.** 새 테이블 2개(마이그레이션은 원가 비중 `cost_item_links` 다음 번호):
   - `user_view_states(user_id, page_key, query text, scroll jsonb null, updated_at)` PK `(user_id, page_key)`
   - `user_drafts(user_id, draft_key, version int, data jsonb, updated_at)` PK `(user_id, draft_key)`
   - 사용자 삭제 시 cascade.
2. #32 열 너비·순서 저장은 **localStorage 그대로**(민감도 낮음).
3. **원가 값은 어디에도 저장하지 않는다**(순매출 계산기 `unitCost`·`miscCost` 등). 저장 직전 스키마에서 제외(zod 로 화이트리스트 필드만).

### 2.2 조회 상태 (필터·검색어·정렬·탭·페이지·선택 분류)
1. **URL 이 기준**(공유 링크·뒤로 가기 유지). 서버 DB 에는 페이지별 "마지막 쿼리"를 저장한다.
2. `page_key` 화이트리스트: 가격 조회, 가격 관리, 원가, 감사, 사용자, 공지 관리, 파츠 매핑, 계산기(탭). 그 외 키 저장 거부.
3. 저장: URL 변경 후 500ms 디바운스 서버 액션. 저장 전 해당 페이지의 기존 파서(zod `.catch`)를 통과한 정규화 쿼리만, 최대 2KB.
4. 복원: **파라미터 없는 모든 진입**에서 RSC 가 저장 쿼리를 읽어 `redirect(path?query)`(깜빡임·이중 요청 없음). 파라미터가 명시된 진입(공유 링크·홈 카드 `?family=` 등)은 저장값보다 우선하며 그 쿼리가 새 저장값이 된다.
   - 루프 방지: 저장 쿼리가 비었거나 파서 통과 후 비면 redirect 하지 않는다.
   - 복원 쿼리도 파서를 다시 통과(변조·권한 밖 열 필터는 버림).
5. **'필터 초기화'·'새로 시작' 은 빈 상태를 저장**해 다음 진입에 이전 조건이 되살아나지 않게 한다.
6. **클라이언트 표 정렬도 URL 로 이동**(`router.replace`, `sort`·`dir` 맨 뒤) — #32 §5 "새로고침 시 해제" 결정을 이 스펙으로 개정. 모달 안 내 견적 목록은 예외(컴포넌트 상태, 저장 안 함).
7. 계산기 탭은 탭 전환 시 `?tab=` 을 URL 에 반영(`router.replace`)해 같은 경로로 저장·복원.
8. 유지 기간: **무기한**(초기화 전까지).

### 2.3 스크롤
1. 대상 `<main>` 스크롤 컨테이너. `user_view_states.scroll = { query, top }` 로 저장(페이지 이탈·`visibilitychange` 시 1회, 진행 중 스크롤마다 저장 금지).
2. 복원은 **현재 쿼리 == 저장된 scroll.query** 일 때만, 데이터 렌더 후 1회 시도(높이가 모자라면 가능한 최대). 조건이 바뀌면 맨 위.
3. 필터·정렬·페이지 변경 시 맨 위로.

### 2.4 입력 초안 (Q5 A)
1. `draft_key` 화이트리스트:
   - `quote`: 견적 계산기 선택값(제품군·단가유형·분류·품목·수량·할인 등 — Dev 가 상태 목록을 PR 본문에 명시)
   - `cart`: 장바구니 라인
   - `margin`: 순매출 계산기(**원가 입력 제외**)
   - `group-solution`: 그룹 솔루션 선택
   - 제외: 관리 화면 등록·수정 모달(정책·원가·공지·사용자), LLM 키 입력.
2. 저장: 변경 후 1s 디바운스 서버 액션, `version` + zod 스키마, 최대 50KB. 알 수 없는 필드는 버림, 스키마 불일치·버전 불일치면 초안 폐기.
3. 복원: 페이지 RSC 가 초안을 읽어 초기 props 로 전달(하이드레이션 안전). 견적 입력은 제품군 → 단가유형 → 분류 → 품목 순서로 재조회하며 복원하고, 중간에 없어진 값이 있으면 그 단계에서 멈추고 안내.
4. 유지 기간: **마지막 수정 후 30일**(Q4 A). 읽을 때 만료분은 무시·삭제.
5. 여러 탭: 마지막 저장 우선(last-write-wins). 탭이 다시 보일 때(`visibilitychange`) 편집 중이 아니면 서버 초안을 다시 읽는다.
6. **장바구니 결함 수정**: sessionStorage 저장 제거(`cart` 초안으로 이전). 남아 있는 `prami.quote.cart.v1` 키는 **이전하지 않고 삭제**(사용자 구분이 없어 다른 사용자 데이터일 수 있음).

### 2.5 가격 변동 (Q2 A)
1. `cart`·`quote` 복원 시 `reprice` dry-run 으로 최신가 확인 → **즉시 최신가로 갱신** + 배너 "가격이 바뀐 품목 N건을 최신가로 갱신했습니다".

### 2.6 복원 안내·초기화 (Q3 A)
1. 입력 초안을 복원한 화면(계산기·장바구니·순매출·그룹 솔루션)에 `role="status"` 배너: "이전 작업을 복원했습니다 (MM-DD HH:mm) · [새로 시작]". Collapse 모션, reduced-motion 준수. 조회 상태 복원에는 배너 없음(칩·필터 초기화가 보임).
2. 화면별 초기화: 표의 '필터 초기화'(A 스펙), 계산기 '새로 시작'(해당 초안 삭제 + 빈 상태 저장), 기존 '견적 초기화'(`cart` 초안 삭제).
3. 전역: 사용자 설정 > **"저장된 화면·입력 초기화"** — 확인 모달 후 본인의 `user_view_states`·`user_drafts` 전부 삭제. #32 열 너비·순서는 대상 아님(문구에 명시: "조회 조건과 작성 중 입력을 지웁니다. 표 열 너비·순서는 각 표의 '열 초기화'로 되돌립니다").

### 2.7 권한·보안
1. 복원 시 현재 권한으로 재검증(권한 밖 페이지 키·열 필터·필드는 버림). 원가 값은 애초에 없음.
2. 저장 액션은 로그인 사용자 본인 행만(user_id 는 세션에서, 클라이언트 입력 불가). 값은 React 텍스트로만 렌더, URL 은 `URLSearchParams` 로 조립.
