# 가격정책 조회(/pricing)에서 가격 변동 비노출

- 요구사항: Main msg_7c04d5c7e351 (2026-10-21, 긴급). 사용자 지시: "가격 정책 조회에서 가격 변동은 보여주면 안 됨". 관리(/admin/policies)는 현행 유지.
- 긴급·소범위라 서브에이전트 검토 생략(변경 대상이 #55·#59 스펙으로 확정, Plan 직접 결정).
- 개정 대상: `cost-ratio-price-change.md` §2.4-1("조회·관리 모두"), `price-change-history-modal.md` §2.2-1("조회·관리 모두") → **관리 화면만**.

## 결정 (Dev는 이 결정을 따른다)
1. 가격 변동 노출 조건 = 관리 화면 모드 **그리고** `pricing.write`(원가 비중의 `cost.read` 게이트와 같은 방식으로 서버에서 판정).
2. /pricing(조회):
   - 가격 변동 열 정의 없음, 셀 버튼·이력 모달 없음, 드로어 "변동 이력 보기" 버튼 없음.
   - **응답에 키 자체 없음**: 조회 모드의 가격 쿼리는 이전가·변동률을 계산하지도 선택하지도 않는다(윈도 조인 제외 — 조회 화면 쿼리 비용도 줄어듦). RSC payload·액션 응답에 `priceChange`·`previousPrice` 등 0.
   - 필터·정렬 화이트리스트에서 `priceChange` 제외 → `f.priceChange.*`·`sort=priceChange` URL 은 무시(기본 정렬, 오류 없음). 저장된 열 레이아웃의 `priceChange` id 는 기존 정규화로 무시.
3. **이력 액션 `getPriceHistoryAction` 권한을 `pricing.write` 로 상향**(조회 권한만으로 호출 불가 — 거부·감사는 기존 runAction 규칙).
4. **Q-V1 = B (사용자 확인, msg_5fe07f1d9556)**: 조회 화면 행 상세 드로어의 "계열 이력" 목록도 제거. 드로어 상세 액션은 **`pricing.write` 이고 관리 모드 요청일 때만** 계열 이력을 반환하고, 그 외(USER 전부, /pricing 에서 연 ADMIN)는 응답에 계열 이력 키 자체가 없다(현재 행 정보만). 모드 값은 클라이언트가 보내도 권한 상향이 불가능(USER 는 항상 이력 없음)하므로 안전.
5. /admin/policies: #55·#59 동작 무변화(회귀 없음).
6. 챗봇: 기존대로 가격 변동 미사용(회귀 1건 유지).
