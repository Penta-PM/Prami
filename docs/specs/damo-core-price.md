# D.AMO 코어 단가 — 계산기·가격 정책 반영 (긴급)

- 요구: Main msg_231bce4f7bb2 (2026-11-05). 사용자 원문 규칙:
  - 코어 단가 Y → 코어 수 입력창을 보여 준다.
  - 코어 수 = 기준 코어수 → 단가만.
  - 코어 수 > 기준 → 단가 + (추가 코어 × 1코어 단가). 예: 6코어 = 4코어 기본 단가 + 2 × 1코어 단가.
- 긴급: "바로 반영하여 main으로 합치고 3000번 포트로 보여줄 것". 흐름은 B′(`deploy-on-merge.md`)이고 QA는 생략합니다.
- 병렬 검토 결과: UI/UX와 기능/기술 검토가 상충하지 않았습니다. 보완되는 내용은 함께 반영했습니다. 사소한 모호점은 Main 지시("합리적 기본값으로 정하고 보고에 명시")에 따라 §3에서 Plan이 정했습니다.

## 1. 현황 (검토 확인)
- 엑셀 판매단가 `RAW` 시트의 `코어단가유무`·`기준코어수`·`단가(1코어)` 세 컬럼은 이미 다음 경로에서 처리됩니다.
  - 임포트: `apply-steps.ts:85-90`
  - DB 컬럼: `sales_prices.has_core_price` / `base_core_count` / `unit_price_per_core`
  - 정책 편집 폼(`PolicyFormModal`)과 상세 드로어
  - → **임포트, 스키마, 정책 편집은 변경하지 않습니다. 마이그레이션도 없습니다.**
- 계산기, 견적 저장 시 재가격화, PDF, 공유 화면은 이 값을 쓰지 않습니다. 이번에 바꿀 것이 이 부분입니다.
- LAN DB의 Y 행은 전부 D.AMO 본품(S/W)이고 단위는 `서버`입니다. 다른 제품군은 모두 N입니다.
- 기준코어수는 **(품번, 단가유형) 행마다 다릅니다**(예: 정상판매 4, ASP 8). 그래서 선택한 행의 값을 씁니다.
- 1코어 단가는 "단가 ÷ 기준"이 아니라 따로 정한 증설 단가입니다. 사용자가 준 공식과 맞습니다.

## 2. 계산 규칙 (공용 순수 함수 1개)
- `src/lib/pricing/quote.ts`에 `coreUnitPrice(row, cores)`를 추가합니다.
  - **코어 적용 조건:** `hasCorePrice && baseCoreCount >= 1`. 조건이 맞지 않으면 원래 단가를 그대로 돌려줍니다. N 품목과 다른 제품은 결과가 바뀌지 않습니다.
  - 적용할 때: `unitPrice + max(0, cores − base) × unitPricePerCore`.
  - `cores`가 없으면(undefined) 기준값으로 봅니다.
- 이 결과를 `computeLine`의 본품가(basePrice)로 넘깁니다. 그 뒤 계산은 기존과 같습니다.
  - `(코어 반영 단가 + Σ파츠 + Σ결합형) × 수량`, 그다음 라인 할인, 그다음 KRW 천 원 단위 절삭.
  - 코어 수는 **서버 1대당** 값입니다. 파츠와 결합형 단가는 코어 수와 관계없습니다.
- 클라이언트(계산기·장바구니)와 서버(`reprice.ts` 저장 재계산, `repriceDryRun` 복원)는 **반드시 같은 함수**를 씁니다. 다른 함수를 쓰면 저장할 때 가짜 단가 보정이 생깁니다.

## 4. 저장·표시
- **견적 라인 스냅샷**
  - `quote_lines.unit_price`에 **코어 반영 단가**를 저장합니다. 기존의 `수량 × 단가` 표시가 그대로 맞게 됩니다.
  - `options` jsonb에 `core: { cores, baseCoreCount, unitPricePerCore, baseUnitPrice }`를 더합니다.
  - 이전에 저장된 견적은 `core`가 없으므로 코어 없는 견적으로 처리합니다. 금액은 바뀌지 않습니다.
- **입력 스키마:** `quoteLineSchema`와 `cartLineDraftSchema`에 `coreCount?: int`(선택 필드)를 추가합니다. 하위 호환입니다.
- `catalog.ts`의 `QuoteItem`에 코어 3필드를 추가합니다. 단가와 같은 DISTINCT ON 행에서 가져옵니다.
- **계산기 STEP3:** Y 행(D4 제외)을 고르면 수량 아래에 "코어 수" 행이 `Collapse`로 펼쳐집니다.
  - 숫자 입력(`inputMode="numeric"`, step 1)과 −/+ 버튼을 둡니다. −/+만 두지 않습니다.
  - 보조문구: "기준 N코어 포함 · 초과 1코어당 ₩x"
  - 접근성: `<label>`을 연결하고, 오류는 `aria-invalid`와 `aria-describedby`로 연결합니다. 버튼 이름은 "코어 수 감소"/"코어 수 증가"입니다.
  - 모바일에서는 수량과 코어 수를 세로로 쌓습니다.
- **품목 목록:** Y 품목의 가격 옆에 "기준 N코어" 배지를 붙입니다.
- **STEP6 결과:** 코어 품목이면 "할인 적용 전 금액" 위에 내역 한 줄을 둡니다: `기본 단가(4코어) ₩A + 추가 2코어 × ₩B = ₩C`. `aria-live="polite"`를 줍니다.
- **장바구니:** 요약에 `6코어` 토큰을 넣습니다. 초안(`QuoteFormState`)과 `CartLine`에 코어 수를 저장합니다. 저장된 견적을 다시 담을 때(`linesFromSavedQuote`) `options.core.cores`로 복원하고, 값이 없으면 기준값을 씁니다.
- **견적서(`QuoteSheet`)·PDF(`QuotePdf`):** 라인 아래에 기존 옵션 하위 줄과 같은 형식으로 `+ 추가 코어 2 × ₩B (기준 4코어 포함, 총 6코어)`를 넣습니다. 코어를 추가하지 않았으면(코어 수 = 기준) `기준 4코어` 한 줄만 넣습니다.
- **가격 정책 표**(조회 /pricing와 관리 화면 공용): 열은 추가하지 않습니다.
  - Y 행(D4 제외)만 판매가 칸 아래에 보조 한 줄 `기준 4코어 · +1코어 ₩x`를 넣습니다(11px, `text-text-tertiary`).
  - N 행은 바뀌지 않습니다. 사용자별로 저장된 열 레이아웃에도 영향이 없습니다. 1코어 단가는 판매가라서 USER에게도 보여도 됩니다.
- **챗봇:**
  - `price_lookup`의 `PriceSchema`에 Y 행(D4 제외)일 때만 `baseCoreCount`·`unitPricePerCore`를 선택 필드로 추가합니다.
  - 규칙 응답(`respond.ts`)의 판매가 문장 뒤에 "(기준 N코어, 추가 1코어당 ₩x)"를 덧붙입니다.
  - 코어 견적 계산과 계산기 링크 프리셋은 비범위입니다.
