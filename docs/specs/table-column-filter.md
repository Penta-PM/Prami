## 2. 기술 결정 (Dev는 이 결정을 따른다)

### 2.1 필터 모델 (공용)
1. `lib/table/filter.ts`: 연산자 모델·URL 코덱·zod·클라이언트 술어. 열 정의에 `filter?: { ops, options? }` 추가(`types.ts`).
2. 열 타입별 연산자:
   - text: `has`(포함, 기본)·`eq`(같음). 비교는 #32 와 같은 ASCII 소문자화(`asciiLower`).
   - status/enum: `in`(다중 선택, 순서는 `statusOrder`). 값은 enum 으로 검증.
   - number/money: `gte`·`lte`(범위). 같은 열에 통화가 섞이면 **통화 조건이 하나로 정해졌을 때만** 금액 범위 활성(아니면 비활성 + "통화를 먼저 선택하세요").
   - date: `gte`·`lte`(기간, ISO date). 감사는 기존 KST 해석 재사용.
   - none·목록·JSON 열(감사 변경 전/후, 파츠 장착 파츠 등): 필터 없음.
3. 조합: 모든 조건 AND. 같은 열에 `gte`+`lte` 동시 허용.
4. 한도: 값 100자, `in` 값 20개, 조건 10개. 초과·형식 오류는 그 조건만 버림.

### 2.2 URL (서버·클라이언트 공통)
- 형식 `f.<colId>.<op>=<value>` (`in` 은 쉼표 구분, 값은 `URLSearchParams` 로 인코딩). 키 정규식 `^f\.([A-Za-z]+)\.(has|eq|in|gte|lte)$`.
- `sort`·`dir` 는 계속 맨 뒤(#32 §3). 필터 변경 시 `page=1`.
- 클라이언트 표도 필터를 URL 에 둔다(`router.replace`, 히스토리 누적 없음). **예외**: 모달 안의 내 견적 목록은 컴포넌트 상태(모달은 URL 상태가 아님).

### 2.3 서버 필터
1. 표별 `FILTER_SPEC: Record<colId, { type, ops, sql }>` 화이트리스트. 열 식은 #32 정렬 맵(`sort-sql.ts`)의 식을 재사용. 스펙에 없는 열·연산자는 무시.
2. SQL 은 drizzle 바인딩만(문자열 보간 0):
   - `has`: `strpos(lower(x COLLATE "C"), lower($1 COLLATE "C")) > 0` (LIKE 이스케이프 불필요, 클라이언트 비교와 일치)
   - `eq`: `lower(x COLLATE "C") = lower($1 COLLATE "C")`
   - `in`: `x = ANY($1)`(검증된 enum 값), number/date: `>=`·`<=`.
   - 가격 품명의 NBSP 정규화는 기존 `q` 처리와 동일.
3. count·rows·CSV 가 같은 WHERE 를 쓴다. 감사 CSV href(`filterToQuery`)에 필터 전파.
4. **필터 화이트리스트 ⊆ 그 역할이 볼 수 있는 열.** 원가 비중(`costRatio`)은 필터 불가. 원가 표는 기존 `assertCostAccess` 유지.

### 2.4 기존 필터 정리 (조건 중복 0)
- 가격: 대/중/소분류 연쇄·적용기간 기준(dateMode·from·to)·검색 `q` **유지**. 이와 같은 의미의 열(대·중·소분류, 적용시작일, 품목명)은 열 필터를 만들지 않는다.
- 원가: 제품군 탭·기간·검색 **유지**, 같은 의미의 열은 열 필터 없음.
- 감사: 기존 GET 폼(시작·종료일, 행위, 사용자, 초기화)을 **제거하고 열 필터로 흡수**. 열 필터가 기존 파라미터(`from`·`to`·`action`·`actor`)에 그대로 기록(별칭). `action` 은 다중 선택으로 확장(쉼표 구분, 기존 단일 값 URL 호환).

### 2.5 UI
1. 표 위 툴바: **"＋ 필터"** 버튼 → 열 선택 → 연산자·값 팝오버 → "적용"(Enter) 으로 확정(키 입력마다 요청 금지).
2. 적용 조건은 칩(`<열>: <조건>` + × "＜열＞ 필터 해제"), 끝에 **"필터 초기화"**. 칩 바는 줄바꿈.
3. 필터가 걸린 열 헤더에 점 표시(`aria-hidden`). 헤더 안 버튼·필터 행 금지(#32 헤더 접근성 이름·리사이즈·드래그 충돌).
4. **필터 초기화** = 열 필터 + 그 화면의 기존 필터 + 정렬 해제(#32 §9.3 Q3). 가격·원가에도 이 버튼 신설. '열 초기화'(너비·순서)와 별개.
5. 팝오버 프리미티브 신설(`components/ui/popover`): 비모달 `role="dialog"`, `aria-label="<열> 필터"`, 열리면 첫 입력 포커스, Esc 는 팝오버만 닫고 트리거로 포커스 복귀(모달 안에서는 전파 차단 — 모달 유지), 바깥 클릭 닫힘, 폭 `min(320px, 100vw - 32px)`. 모션 `fade`/`scaleIn` 토큰, reduced-motion 준수. 터치에서도 사용 가능.
6. 건수: 클라이언트 표 "전체 N건 중 M건"(필터 있을 때), 서버 표는 기존 total. 결과는 기존 `aria-live` 로 "필터 적용 · M건".
7. 빈 상태 2종: 데이터 없음("등록된 … 없습니다") / 필터 결과 없음("조건에 맞는 결과가 없습니다" + [필터 초기화]). 사용자 표에 빈 상태 신설.
8. 색은 기존 토큰(`chipClass` 등)만 — 라이트·다크.
